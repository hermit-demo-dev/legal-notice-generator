# 莘聖沐光居存證信函產生器

純 HTML、CSS、JavaScript 網頁，可直接部署 GitHub Pages，不需要 Python、伺服器、API 金鑰或付費服務。JSZip、PDF-LIB、fontkit及繁中字型均隨網站提供，不依賴第三方 CDN。

## 使用

填寫姓名、地址、戶別、樓層、簽約／交寄日期、契約總價，以及每張發票的金額。頁面金額統一以「萬元」輸入及顯示（例如總價1678、發票35、15、11、23），可填最多4位小數，精確至1元；產生的信函金額亦統一使用萬元。發票總和就是已繳款，信託金額同步沿用此數字，毋須重複輸入；須確認銀行資料與合計相符。確認範本適用情況後按「產生 Word 與 PDF」，可分別下載四份檔案，或一起下載ZIP：

- `一般信函_20261028.docx`：頁面名稱為「一般信函」，沿用原稿版式、保留紅字欄位。
- `存證信函_20261028.docx`：保留指定郵局格式，正文改為主文件中的一般Word表格，可直接點入儲存格刪改；黑色框線至少0.75pt，每頁20欄10行。郵局表頭／計費／用印區保留為高解析固定版型。
- `一般信函_20261028.pdf`：同一份文字，以繁中字型與黑字另行排版，方便列印。
- `存證信函_20261028.pdf`：使用指定Word格式匯出的空白向量PDF及相同20×10文字分頁，保留清晰框線。

存證信函Word與PDF最後另附一頁「副本收件人聯記表」，採無郵局表頭的獨立剪貼頁，有虛線框及浮貼提示，可依郵局指示剪下浮貼第一頁。聯記表不再混入正文的每字格線，尺寸約116×40毫米。下載畫面會分開顯示正文頁數及剪貼頁；例如正文9頁加剪貼頁1頁，檔案共10頁，郵局頁首的正文總頁數仍填9。

PDF直接在瀏覽器製作，內嵌繁中字型，並非把產生後的Word送往外部轉檔。一般信函PDF與Word內容相同，換行、字型及分頁可能不同；PDF為黑字列印版，Word保留紅字供編修。Word下載後的手動修改不會自動同步到既有PDF；請重新在網頁輸入並產生。郵局版PDF與Word使用相同每格一字與頁數。首次產生需載入約10MB繁中字型，之後通常可由瀏覽器快取。

檔名日期代表範本版本，文內交寄日期採使用者輸入。四份文件最後只保留「寄件人簽章：」，其後留白供本人親簽，不自動填入姓名。附件列明但不會自動附加；附件標題的紅字保留，不另要求輸入重複資訊。

本工具沿用2026年10月28日信函文字，專供同建案且條款、停車空間描述及未收退款情況相符的已購戶參考。違約金依原稿按總價15%計算、以已繳款為上限，四捨五入至元。第五及第七點期限均為「本函送達後14日內」，不依交寄日推算送達日。利息主張保留原文，未估算利息金額。若信託金額與發票合計不同，請勿勾選適用確認，應先調整範本，不可直接使用本工具。

## 放到 GitHub 個人網頁（免費）

第一次部署可依照同資料夾的 [GitHub部署說明](GitHub部署說明.md)，從建立儲存庫、上傳檔案到啟用Pages逐步操作。

GitHub Free 可對公開儲存庫啟用 Pages。**只上傳本資料夾內的內容**，不要上傳整個案件資料夾、收據、合約照片、銀行截圖或 HANDOFF.md。

1. 在 GitHub 建立公開儲存庫。個人首頁可命名 `你的帳號.github.io`；也可建立一般專案名稱，例如 `muguang-letter`。
2. 把本資料夾內的 `index.html`、`styles.css`、`app.js`、`generator.js`、`pdf-generator.js`、`assets/`、`vendor/`、`.nojekyll` 等上傳至儲存庫根目錄，保留子資料夾結構；請勿遺漏字型與PDF底版。
3. 進入 **Settings → Pages → Build and deployment**，選 **Deploy from a branch**，選 `main` 與 `/(root)`，按 **Save**。
4. 等待部署完成，使用 Pages 顯示的網址。個人首頁為 `https://你的帳號.github.io/`；一般專案為 `https://你的帳號.github.io/muguang-letter/`。本站使用相對路徑，兩種都可使用。
5. 實際填寫測試資料、下載Word及PDF並開啟核對，確認後再分享網址。

官方說明：https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

網站不傳送、不儲存表單資料，沒有分析追蹤。GitHub 仍會接收到一般網站請求，並依其政策記錄訪客IP；這不等於表單資料上傳。公開儲存庫中的法律範本及程式可被任何人讀取。

## 本機預覽與驗證

可在本資料夾使用任何靜態網頁伺服器（例如 `python -m http.server 8765 --bind 127.0.0.1`），再開啟 `http://127.0.0.1:8765/`。因為需要讀取Word範本，請勿直接雙擊HTML以file網址開啟。

若已安裝 Node.js，執行 `node --test tests/generator.test.cjs tests/pdf.test.cjs`。測試會把示例文件寫到上層 `tmp/web-generator/output/` 與 `tmp/pdf-upgrade/output/`；這些個人化輸出不應上傳。

建議直接使用PDF列印，選A4、實際大小／100%比例，關閉節省墨水或草稿列印模式。Word檔以原範本產生，不同Word／文書軟體與字型可能影響顯示。郵局版寄件地址最多48字；請自行核對長地址未超出欄位。

### 修改存證信函Word

下載後如Word出現「受保護的檢視」，確認是自己剛產生的檔案後，按「啟用編輯」。新版正文是主文件內的一般表格，可以直接點入字格輸入、選字及刪除，不必進入圖形群組。程式沒有設定密碼或限制編輯。

每格一字的固定郵局格式，在刪除某格文字後不會自動把其他格文字往前補；大量增刪時須自行重排字格。一般信函Word適合先進行整段編修。寄件姓名及地址位於頁首，可雙擊頁首後編輯。修改Word後，原有PDF不會同步改變，應從修改後的Word另存PDF。

## 維護

`assets/original.docx` 為去除作者中繼資料並替換個人化欄位的原稿；`assets/postal.docx` 保存可直接編輯的Word版型，郵局表頭及用印區採指定Word匯出的4倍解析度圖稿，並拆成僅位於正文上方與下方的兩張獨立圖片。沒有整頁圖片，也沒有覆蓋正文的浮動物件。正文格線為一般Word表格，文字不在圖形群組內。`assets/content.json` 的postalTable保存20×10正文加行列標示的原生表格，postalEditing為body-table。頁首有姓名、地址、總頁數三個獨立文字框。

`assets/postal-blank.pdf` 是從指定Word格式匯出的空白向量頁，PDF仍使用此向量版型，未改成圖片；`assets/pdf-layout.json` 記錄其欄位及格線定位。Word的末頁剪貼聯記表使用獨立section與空白頁首，content.json的ccSlipWord保存分節及剪貼框；PDF使用ccSlip設定另建空白末頁。letterPages僅計正文，pages包含末頁剪貼表。

若更新法律正文，須同步更新原稿範本與content.json；若更新郵局格式，須同步更新表格、固定版型、空白PDF及定位資料，再重新測試、開啟Word與渲染PDF檢查。不能把正文表格重新放回DrawingML／VML群組文字框，也不能使用會橫跨正文區的整頁圖片；即使設定為文字背後，仍可能干擾選取。測試會確認兩張圖片的範圍完全避開正文。第三方授權與來源見 `vendor/` 中的授權文件，以及 `assets/Noto-LICENSE.txt`、`assets/FONT-SOURCE.txt`。


## 手機與日期輸入

網頁會依裝置寬度自動切換版面，不需另一個網址。手機／平板採單欄表單，字體與觸控按鈕放大，下載區位於表單下方。購買戶別提示為輸入A或B，產生的契約物件名稱採「第5樓第A戶」格式（先樓層、再戶別）。簽約日期以年／月／日選單選擇，初始停在2023年11月，日期仍留空，避免誤將預設日視為實際簽約日。可切換其他年月；切換年月後須重新選日，閏年天數會自動調整。


## 確認更新版本

本套件網站版本為2026.11.05.4，網頁最下方可看到版本號。更新時請把解壓後的網站內容連同assets資料夾一起覆蓋，不要只替換HTML或JavaScript。版本號正確但文件仍是舊版時，請檢查assets/postal.docx及assets/postal-blank.pdf是否也已上傳。這一版標頭順序為「二、收件人」→「姓名：莘聖建設股份有限公司」→地址。
